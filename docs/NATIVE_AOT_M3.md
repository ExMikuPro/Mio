# Mochi Native AOT · M3：macOS ARM64 原生条件与循环

M0 已在 M4 Pro 执行 `exit(0)`，M1 完成原生整数计算，M2 完成可写全局槽位。M3 在 **不修改 Mochi v14 指令编号、VM 和字节码格式** 的前提下，支持比较、分支、循环与布尔输出。

## 新增 Opcode 支持

| Mochi | ARM64 编码 |
| --- | --- |
| `OpTrue` / `OpFalse` | `MOVZ Xn,#1/0` |
| `OpNot` | `CMP Xn,#0` + `CSET Wn,EQ` |
| `OpEqual` / `OpNotEqual` | `CMP` + `CSET EQ/NE`，支持 int64/bool 同类型相等 |
| `OpLess` / `OpLessEqual` / `OpGreater` / `OpGreaterEqual` | 有符号 `CMP` + `CSET LT/LE/GT/GE` |
| `OpJump` | `B`（按 Mochi 字节目标回填） |
| `OpJumpIfFalse` | `CBZ`（消费栈顶 bool） |
| `OpChant` | int64 继续复用 M1；bool 输出 `hai` / `iie` |
| `OpPop` | 在不同分支中追踪最后一次**实际执行**的值，并在结束时打印 |

M1/M2 的整数算术与 `__DATA` 全局槽位继续复用。

## 控制流正确性

M3 在生成机器码前先完整解码 Mochi 指令，执行前向控制流数据流分析：

- 校验跳转目标是当前 Mochi 指令块的合法边界（允许结束偏移）。
- 每个字节码边界记录操作数栈的**深度与类型**；分支汇合必须一致。
- 每个全局槽位的**确定赋值状态**在汇合点取交集，杜绝分支中未初始化的全局变量被误当作合法值。
- M3 全局槽位仍仅支持 `int64`；布尔仅在表达式栈中暂存。
- 编译时明确拒绝不支持的 Opcode，包括位于不可达路径中的 Opcode。
- 原生跳转采用 PC 相对立即数回填；分支偏移越界则报错，不截断。
- `x9..x15` 仍用于临时操作数栈（最多 7 个值），暂不引入栈溢出保存或寄存器分配。
- `OpPop` 的实际执行状态位于 `x20`，最新表达式值位于 `x19`，类型位于 `x21`，不允许分支跳过时打印旧值。

无 GC、无线程、无用户函数、无虚拟机运行时。生成的程序用 macOS `dyld` 加载，`codesign` 临时签名，然后直接执行 ARM64 指令。


## 已知限制

- M3 只支持 `int64` 全局变量；虽然支持布尔比较/打印，`kaku ok: bool = hai;` 尚不能用 AOT 存储到全局槽位。
- 主程序仅支持基本指令流；函数、闭包、局部槽、Map、数组、字符串、浮点数、除法、GC 等仍显式报错。
- 数据流分析保守：如果不能证明某个全局槽在所有路径上已初始化，AOT 会拒绝该程序。
- M2 的 `__TEXT` 固定单页 16 KiB、`__DATA` 固定一页 16 KiB，AOT 会拒绝超长原生指令序列。
- 原生程序**不继承 Mochi VM 的指令预算**；测试使用外部墙钟超时，未来需要专门设计运行安全模型。
- Linux 上的静态单元测试和隔离指令模拟不能替代 M4 Pro 上的 `codesign`、dyld 与 CPU 实机测试。
